# Backend Deployment Plan — ECS Fargate + RDS

## Stack

| Layer | Technology |
|-------|-----------|
| Runtime | Java 25, Spring Boot 4.1.0, GraalVM native image |
| Container registry | GitHub Container Registry (GHCR) |
| Compute | ECS Fargate (70% Spot + 30% On-demand) |
| Load balancer | Internal ALB → API Gateway v2 (HTTPS) |
| Database | Amazon RDS PostgreSQL |
| Secrets | AWS Secrets Manager |
| DNS | Route 53 → API Gateway custom domain |

---

## Architecture Overview

```
                        Route 53
                   api.my-saloon.online
                          │
                          ▼
              ┌─────────────────────┐
              │   API Gateway v2    │
              │   (HTTP API)        │
              │   VPC Link          │
              └─────────┬───────────┘
                        │
              ┌─────────▼───────────┐
              │  Internal ALB       │
              │  :80 → :8080        │
              └─────────┬───────────┘
                        │
              ┌─────────▼───────────┐
              │   ECS Service       │
              │   my-saloon-dev-api │
              │                     │
              │  70% Fargate Spot   │
              │  30% Fargate        │
              │                     │
              │  min: 1 task        │
              │  max: 5 tasks       │
              └─────────┬───────────┘
                        │
              ┌─────────▼───────────┐
              │   RDS PostgreSQL    │
              │   (default VPC)     │
              │   Single-AZ (dev)   │
              └─────────────────────┘
```

All ECS tasks and RDS run inside the default VPC. Tasks get a public IP (no NAT gateway needed) but the ALB is internal, accessible only via the API Gateway VPC Link.

## CI/CD — GitHub Actions

```yaml
name: Deploy backend

on:
  push:
    branches: [main]
    paths:
      - "src/**"
      - "pom.xml"
      - ".github/workflows/deploy-backend.yml"
  workflow_dispatch:

env:
  REGISTRY: ghcr.io
  IMAGE_NAME: ${{ github.repository }}   # samitkumarpatel/multi-tenant-saloon
  AWS_REGION: eu-north-1
  ECS_SERVICE: my-saloon-dev-api
  ECS_CLUSTER: my-saloon-dev-cluster
  ECS_TASK_DEFINITION: .aws/task-definition.json
  CONTAINER_NAME: api

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      packages: write

    steps:
      - uses: actions/checkout@v4

      - uses: graalvm/setup-graalvm@v1
        with:
          version: '25.1'
          distribution: 'graalvm'
          github-token: ${{ secrets.GITHUB_TOKEN }}
          cache: "maven"

      - name: Log in to GitHub Container Registry
        uses: docker/login-action@v3
        with:
          registry: ${{ env.REGISTRY }}
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}

      - name: Build and push image to GHCR
        id: build-image
        env:
          IMAGE_TAG: ${{ github.sha }}
        run: |
          ./mvnw -B spring-boot:build-image \
            -Dspring-boot.build-image.imageName=$REGISTRY/$IMAGE_NAME:$IMAGE_TAG
          docker push $REGISTRY/$IMAGE_NAME:$IMAGE_TAG
          echo "image=$REGISTRY/$IMAGE_NAME:$IMAGE_TAG" >> $GITHUB_OUTPUT

      - name: Configure AWS credentials
        uses: aws-actions/configure-aws-credentials@v4
        with:
          aws-access-key-id: ${{ secrets.AWS_ACCESS_KEY_ID }}
          aws-secret-access-key: ${{ secrets.AWS_SECRET_ACCESS_KEY }}
          aws-region: ${{ env.AWS_REGION }}

      - name: Render updated task definition
        id: task-def
        uses: aws-actions/amazon-ecs-render-task-definition@v1
        with:
          task-definition: ${{ env.ECS_TASK_DEFINITION }}
          container-name: ${{ env.CONTAINER_NAME }}
          image: ${{ steps.build-image.outputs.image }}

      - name: Deploy to ECS
        uses: aws-actions/amazon-ecs-deploy-task-definition@v2
        with:
          task-definition: ${{ steps.task-def.outputs.task-definition }}
          service: ${{ env.ECS_SERVICE }}
          cluster: ${{ env.ECS_CLUSTER }}
          wait-for-service-stability: true
```

**GitHub Secrets required** (Settings → Secrets and variables → Secrets):

| Secret | Value |
|--------|-------|
| `AWS_ACCESS_KEY_ID` | IAM user access key ID |
| `AWS_SECRET_ACCESS_KEY` | IAM user secret access key |

All other values (`ECS_CLUSTER`, `ECS_SERVICE`, `AWS_REGION`, `CONTAINER_NAME`) are hardcoded in the workflow from the Terraform naming convention.

## IAM — Deploy User

Create IAM user `my-saloon-dev-ci` with this inline policy:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "ECSDescribe",
      "Effect": "Allow",
      "Action": [
        "ecs:DescribeServices",
        "ecs:DescribeTaskDefinition",
        "ecs:DescribeTasks",
        "ecs:ListTasks"
      ],
      "Resource": "*"
    },
    {
      "Sid": "ECSDeploy",
      "Effect": "Allow",
      "Action": ["ecs:UpdateService", "ecs:RegisterTaskDefinition"],
      "Resource": "*"
    },
    {
      "Sid": "PassRole",
      "Effect": "Allow",
      "Action": ["iam:PassRole"],
      "Resource": "arn:aws:iam::257222191091:role/my-saloon-dev-api-exec-role"
    }
  ]
}
```

Image push goes to GHCR via `GITHUB_TOKEN` — no AWS permissions needed for that.

### ECS Task Execution Role

Role: `my-saloon-dev-api-exec-role`
- `AmazonECSTaskExecutionRolePolicy` (managed)
- Inline: `secretsmanager:GetSecretValue` on `arn:aws:secretsmanager:eu-north-1:257222191091:secret:/my-saloon/dev/*`

### ECS Task Role

Role: `my-saloon-dev-api-task-role` — start empty, add permissions as features require (SES, S3, etc.)

## Known Constraints & Future Improvements

| Item | Note |
|------|------|
| WebSocket | API Gateway v2 WebSocket APIs do not support VPC Link. Add WS support via a public NLB when the Spring Boot app implements WebSocket endpoints. |
| Schema migrations | Flyway is enabled in production. Add new schema changes as versioned files `V3__*.sql`, `V4__*.sql`, etc. |
| Database pooling | HikariCP default pool size (10) is fine for 1–2 tasks; tune `maximum-pool-size` if scaling beyond 5 tasks. |
| Aurora Serverless v2 | Migration plan at `wiki/migration-rds-to-aurora-serverless-v2.md` — saves ~$8/month in dev with auto-pause. |
| Private subnets | Currently using default VPC public subnets with `assign_public_ip = true`. A custom VPC module exists at `infrastructure/modules/vpc/` for production hardening. |
| Blue/green deploys | Current workflow does rolling updates. Switch to CodeDeploy blue/green for zero-downtime when needed. |
| Observability | Add AWS X-Ray or OpenTelemetry for distributed tracing across Spring Modulith events. |
